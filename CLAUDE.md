# Analytical-Satsky

Analytical (non-simulation) model predicting how many satellites from mega-constellations
(Starlink, OneWeb, Guowang, Qianfan, ...) pass through a telescope's field of view during an
observation. Adapts [Bassa et al. 2022](https://www.aanda.org/articles/aa/abs/2022/01/aa42101-21/aa42101-21.html)
for radio telescopes; underlies Cerardi, Tolley & di Vruno (2026, A&A). See [README.md](README.md)
for the science overview and quick start.

## API surface: stable vs in-development

The package has two parallel model implementations. Do not conflate them.

**Stable, tested, documented** (exported from `analytical_satsky/__init__.py`, covered by
[docs/api.md](docs/api.md)):
- `load_constellation`, `list_constellations` ([loaders.py](analytical_satsky/loaders.py))
- `SingleShellObs`, `MultiShellObs` ([shell_obs.py](analytical_satsky/shell_obs.py))
- `compute_occupancy_fraction` ([model.py](analytical_satsky/model.py))
- `plot_sky_map` ([plot_utils.py](analytical_satsky/plot_utils.py))

This path parametrizes targets by **local hour angle** (`target_lha`), not RA, specifically to
drop time-dependence (shells are defined w.r.t. Earth's instantaneous rotation axis — see
[docs/model.md](docs/model.md)).

**In development, not exported, untested, undocumented**: `SingleShellFoV`, `MultiShellFoV`,
`SingleShellFlux`, `MultiShellFlux`, `IntegralObsModel` in shell_obs.py, plus
[large_fov_model.py](analytical_satsky/large_fov_model.py). This is the large-FoV / satellite-catalogue
sampling path mentioned as "in development" in the README roadmap. It parametrizes targets by
**true RA/Dec + an explicit MJD time** instead of LHA — a different coordinate convention from the
stable path. Treat as WIP; don't assume test or doc coverage.

`model.py` also has a free-function version of the stable path's physics
(`compute_shell_satellite_density`, `compute_total_satellite_density`, `simulate_exposed_time`) that
duplicates what `SingleShellObs`/`MultiShellObs` do via cached properties. The class-based path is
the one actually used by the README/docs — treat the free functions as legacy-ish unless told otherwise.

`_legacy.py` is explicitly deprecated (see its own docstring); kept only because
`tests/test_internal.py::test_exposure_fraction` checks it against the current
`compute_occupancy_fraction` for equivalence.

## Unit conventions

- Constellation shell tables (`i`, `h`, `n` columns — inclination in deg, altitude in km, satellite
  count) are **plain floats**, never astropy `Quantity`. See [docs/constellations.md](docs/constellations.md).
- Internal `model.py`/`shell_obs.py` functions expect astropy `Quantity` (radians for angles, meters
  for distances) and convert shell-table floats into Quantities at the boundary.
- This float-vs-Quantity boundary is the most common source of unit bugs when touching loaders or
  model code — check which side of it you're on.

## Packaging

- setuptools + `pyproject.toml` (no `setup.cfg`); `setup.py` is a stub for editable installs.
- Install: `pip install -e .` (add `[dev]` extra for pytest/build/twine).
- Shell CSVs are packaged data, declared via `[tool.setuptools.package-data]` in pyproject.toml
  (`"analytical_satsky.shells" = ["*.csv"]`) and loaded at runtime via `importlib.resources`
  ([loaders.py](analytical_satsky/loaders.py)) — not read from a relative filesystem path.

## Docs

- [docs/api.md](docs/api.md) is now **autogenerated** from docstrings via `mkdocstrings`, for every
  symbol in `__init__.py`'s `__all__` (`load_constellation`, `list_constellations`,
  `compute_occupancy_fraction`, `plot_sky_map`, `SingleShellObs`, `MultiShellObs`). Each entry is a
  `::: analytical_satsky.<symbol>` directive — do not hand-edit prose back into `api.md` for these
  symbols; edit the source docstring instead and the page updates itself. Hand-written prose (intro,
  category grouping, cross-refs to `model.md`/`constellations.md`) is still fine to edit directly in
  `api.md`, since `mkdocstrings` only expands the `:::` lines.
- Toolchain: **mkdocs + mkdocstrings (griffe) + mkdocs-material** (`docstring_style: numpy`,
  `show_root_heading: true` — required or the symbol name doesn't render above its docs), configured
  in `mkdocs.yml` at the repo root. Installed via the `docs` extra in `pyproject.toml`
  (`pip install -e ".[docs]"`). Dark-mode toggle is enabled in `theme.palette`.
- Preview locally with `mkdocs serve` (live-reloads on changes to `docs/` or `mkdocs.yml`).
- Deployed to **GitHub Pages** at `nicolas-cerardi.github.io/Analytical-Satsky` via
  [.github/workflows/docs.yml](.github/workflows/docs.yml), using `actions/configure-pages` +
  `actions/upload-pages-artifact` + `actions/deploy-pages` (not `mkdocs gh-deploy`, to avoid a
  `gh-pages` branch). Pages source is set to "GitHub Actions" in repo Settings → Pages.
- **Remaining/known gaps:**
  - The workflow triggers on push to `dev_version2`. Once this branch is merged into `main`,
    update the `on.push.branches` list in `docs.yml` to `main`.
  - The `github-pages` deployment environment has its own branch protection rule (Settings →
    Environments → `github-pages` → Deployment branches and tags), separate from the Pages source
    setting — `dev_version2` had to be added there explicitly before the first deploy would succeed.
    If the trigger branch changes (e.g. to `main`) or a new environment gets created, check this
    setting again.
  - `large_fov_model.py` and the WIP `shell_obs.py` classes (`SingleShellFoV`, `MultiShellFoV`,
    `SingleShellFlux`, `MultiShellFlux`, `IntegralObsModel`) are deliberately **not** referenced in
    `api.md` — they have no docstrings yet, so a `:::` directive would render broken/empty. Add
    docstrings first if/when that path graduates out of WIP and gets added to the docs.
- [docs/model.md](docs/model.md) documents the model's physical assumptions (circular orbits,
  constant Earth radius, straight-line/constant-velocity FoV integration) — read before changing
  any equation in model.py.

## Tests & CI

- `pytest tests/` — three files: `test_imports.py` (import smoke test), `test_internal.py` (unit
  correctness + physical sanity checks, e.g. zero density at low inclination / high declination),
  `test_minimal_code.py` (shape/sign checks on the README quick-start path).
- GitHub Actions ([.github/workflows/tests.yml](.github/workflows/tests.yml)) runs pytest on
  Python 3.10 and 3.12. No lint or type-check step currently.
- Test coverage is effectively limited to the stable small-FoV path; the large-FoV/Flux/Integral
  classes and `plot_utils.py`/`large_fov_model.py` have no tests.
